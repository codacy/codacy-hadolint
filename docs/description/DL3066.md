## Non-numeric user-id may not be resolvable by host system

### Problematic code:

```dockerfile
USER foobar
```

### Correct code:

```dockerfile
USER 1234
```

### Rationale:

In Kubernetes, when runAsNonRoot: true is set, the kubelet cannot resolve a symbolic username from the container image (no access to /etc/passwd). This causes pod startup failure with an error like:

```
Error: container has runAsNonRoot and image has non-numeric user (app), cannot verify user is non-root
```

Using a numeric UID allows to immediately validate non‑root execution.
